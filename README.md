# SSH-Tunnel

Клиент для Windows на Rust. Поднимает системный IPv4-туннель через SSH
на порту 22 или локальный SOCKS5-прокси. В обоих режимах можно войти
по паролю или SSH-ключу. Подключение работает в фоне.

## 1. Подготовить сервер

Нужны Debian или Ubuntu, вход по SSH на порту 22 от root, доступ к
`/dev/net/tun` и к репозиториям пакетов дистрибутива. При первом
подключении в режиме **System VPN (IPv4)** клиент запустит установщик
по SSH, если обработчик ещё отсутствует или IPv4 forwarding выключен.
Установка может занять несколько минут. Для ручной установки скопируй
[install-server.sh](install-server.sh) на сервер и выполни:

```sh
sudo sh install-server.sh
```

Установщик добавит недостающие пакеты, проверит TUN, включит IPv4 forwarding
и установит обработчик в `/usr/local/libexec/ssh-tunnel-vpn`. Обработчик
запускается внутри SSH-сеанса от root, поддерживает одно VPN-подключение
и удаляет временные правила маршрутизации и NAT при штатном завершении.
Существующие настройки входа по SSH определяют, можно ли подключаться
с выбранным способом авторизации.

Для **SOCKS5** достаточно SSH-сервера с разрешённым TCP-форвардингом.

Если автоматическая установка завершится ошибкой, клиент покажет вывод
сервера. Установщик можно повторно запустить вручную на сервере из
профиля подключения.

## 2. Установить клиент Windows x64

Скачай `ssh-tunnel-setup-x64.exe` из [последнего релиза](https://github.com/d1llr/sshvpn/releases/latest).
Установщик добавит ярлыки SSH Tunnel на рабочий стол и в меню «Пуск» и установит Wintun вместе с приложением.
В Windows должен быть включён **OpenSSH Client**.

В установленном приложении нажми **Проверить обновления** при отключённом
туннеле. Клиент скачает более свежий стабильный релиз с GitHub, сверит
SHA-256 установщика, запустит обновление и закроется. Установщик снова
откроет приложение после обновления. Профили хранятся отдельно в
`%LOCALAPPDATA%` и сохраняются при обновлении.

Для закрытого репозитория добавь пользовательскую переменную Windows
`SSH_TUNNEL_GITHUB_TOKEN` с fine-grained токеном GitHub, ограниченным
репозиторием `d1llr/sshvpn` и разрешением **Contents: Read-only**.
Перезапусти клиент после настройки переменной. Каждый пользователь
закрытых релизов должен иметь собственный доступ к репозиторию.

### Сборка из исходников

Установи [Rust и Cargo](https://rustup.rs/) и включи компонент
**OpenSSH Client** в Windows. Выполни в PowerShell:

```powershell
git clone https://github.com/d1llr/sshvpn.git
cd sshvpn
rustup toolchain install stable-x86_64-pc-windows-gnu --profile minimal
cargo +stable-x86_64-pc-windows-gnu build --release --locked
```

Исполняемый файл появится в `target\release\ssh-tunnel.exe`.
Для сборки через MSVC используй `cargo build --release --locked` с
установленными Visual Studio Build Tools для C++ и Windows SDK.

Для **System VPN (IPv4)** скачай официальный архив [Wintun](https://www.wintun.net/)
и скопируй из него `wintun\bin\amd64\wintun.dll` в `target\release`,
рядом с `ssh-tunnel.exe`.

Чтобы собрать установщик, установи [Inno Setup](https://jrsoftware.org/inno-setup/downloads),
положи `ssh-tunnel.exe`, `wintun.dll` и `WINTUN-LICENSE.txt` в папку сборки
и вызови `ISCC.exe /DAppVersion=0.4.4 /DPayloadDir=ПОЛНЫЙ_ПУТЬ installer\ssh-tunnel.iss`.
Версия должна совпадать с `Cargo.toml`, а тег релиза — иметь вид `v0.4.4`.

## 3. Подключиться

1. Запусти `ssh-tunnel.exe`. Windows запросит права администратора.
   Подтверди запрос для **System VPN (IPv4)**. Если отменить запрос,
   можно пользоваться режимом **SOCKS5**.
2. Выбери режим рядом с кнопкой **Подключить** и укажи сервер и SSH-пользователя. Для системного VPN
   используй root, для прокси — пользователя с доступом к SSH.
3. Выбери **Пароль SSH** или **SSH-ключ** и нажми **Подключить**. При первом
   подключении OpenSSH автоматически добавляет ключ сервера в
   `%USERPROFILE%\.ssh\known_hosts`. Подключение с изменившимся ключом
   отклоняется. Если нужно проверить подлинность при первом подключении,
   заранее добавь ключ, полученный из доверенного источника. В режиме прокси
   укажи `127.0.0.1:1080` в настройках приложения или используй
   **Копировать адрес прокси**, если выбрал другой локальный порт.
4. Нажми **Отключить**, чтобы закрыть туннель.

## Профили

Нажми **Новый профиль** в боковой панели, задай имя и параметры подключения,
введи пароль или парольную фразу при необходимости и нажми **Сохранить**.
Нажми на имя сохранённого профиля, чтобы выбрать его, затем нажми **Подключить**.
Кнопка с карандашом
открывает настройки и позволяет изменить или удалить профиль.

Windows шифрует сохранённый пароль или фразу ключа через DPAPI для текущей
учётной записи. При редактировании поле остаётся пустым. Введи новое
значение, чтобы заменить сохранённое, или выбери **Забыть пароль**
и сохрани профиль, чтобы его удалить. После смены сервера, логина или ключа
введи соответствующий пароль заново.

Клиент хранит профили и последний выбор в
`%LOCALAPPDATA%\SshTunnelClient\profiles.json`. Если найден профиль предыдущей
версии из `profile.json`, клиент импортирует его при первом запуске.

## Приглашения через SSH

На VPS с Debian или Ubuntu обработчик устанавливается автоматически при
подключении клиента **System VPN (IPv4)** от `root`, в том числе если
основной VPN уже установлен. При необходимости можно запустить
`sudo sh install-invitations.sh` вручную. Скрипт проверяет конфигурацию
OpenSSH до её перечитывания. Публичное подключение идёт через TCP-порт 22.
Для выдачи приглашений нужен сохранённый профиль с SSH-входом от `root`
и предварительно проверенный ключ сервера в `known_hosts`.

1. В профиле владельца нажми **Поделиться**. Отправь строку приглашения
   и отдельный код расшифровки разными каналами. Временный ключ действует
   30 минут и позволяет активировать приглашение один раз.
2. Получатель нажимает **Импортировать приглашение**, вводит строку и код.
   Его клиент проверяет ключ сервера, создаёт постоянную пару Ed25519 и
   передаёт серверу публичный ключ. Приватный ключ хранится на ПК получателя.
3. Профиль сохраняется с режимом **SOCKS5**. Рядом с кнопкой подключения
   можно выбрать **System VPN (IPv4)**. Для этого владелец должен один раз
   подключиться от `root` в режиме System VPN (IPv4) обновлённым клиентом.
   Обновление сервера также включает IPv4 для ранее активированных профилей.
   На сервере может работать один системный IPv4-туннель одновременно,
   поэтому владелец должен отключиться, прежде чем подключится получатель.
   У приглашённого пользователя нет интерактивной оболочки и обратного
   форвардинга. При необходимости ограничь доступ к внутренним сервисам
   отдельными сетевыми правилами.
4. В профиле владельца открой **Выданные приглашения**. Список показывает имя
   получателя, статус и последний успешный SSH-вход с постоянным ключом
   по журналу сервера. Время указано в UTC. После очистки журнала старые
   подключения могут быть недоступны. Чтобы закрыть доступ, нажми
   **Отозвать** рядом с получателем и подтверди действие.
   Имя можно задать при создании приглашения. Для старых приглашений
   без имени отображается SSH-пользователь `stv_…`.

Закрытие окна сворачивает клиент в трей и сохраняет подключение.
Двойной щелчок по значку открывает окно. Команда **Выйти** в меню трея
отключает туннель и завершает приложение.

## Маршрутизация

Чтобы выбрать программы, открой профиль **System VPN (IPv4)** и выбери
**По приложениям**. Нажми **Выбрать из запущенных**, чтобы найти программу
по имени или пути и добавить её из списка с иконками. Можно также нажать
**Выбрать файл (.exe)**. Для одного профиля
можно добавить несколько файлов. После подключения новые TCP-соединения
распознанных приложений идут через SSH SOCKS5. На сервере должен быть
разрешён TCP-форвардинг. Перезапусти приложения, если у них уже открыты
соединения. Процессы, которые Windows не позволяет сопоставить с файлом,
и системная служба DNS могут использовать обычное подключение.
Режим блокирует перехваченный UDP выбранных приложений, включая QUIC.
Правила не действуют до запуска либо после остановки сетевого помощника.
SSH-адрес исключён из маршрута помощника, чтобы не зациклить соединение.

Для сборки этого режима добавь в папку сборки `sing-box.exe`, `libcronet.dll`
и `LICENSE` (под именем `SING-BOX-LICENSE.txt`) из официального архива
[sing-box v1.14.4 Windows x64](https://github.com/SagerNet/sing-box/releases/tag/v1.14.4).

Для раздельной маршрутизации открой профиль **System VPN (IPv4)**,
выбери **Список CIDR**, введи IPv4-диапазоны и сохрани профиль. Принимаются
префиксы от `/1` до `/32`, например `192.0.2.0/24` и `198.51.100.10/32`.
Через Wintun идут пакеты с адресами назначения из списка. DNS и IPv6
продолжают использовать обычные настройки Windows.

Системный VPN направляет IPv4-трафик по умолчанию через Wintun, включая UDP.
Более специфичные маршруты, например к локальной сети и SSH-серверу,
сохраняют приоритет. На адаптере используются DNS `1.1.1.1` и `1.0.0.1`.
Публичный IPv6 без более специфичного маршрута направляется в Wintun
и отбрасывается. Системный DNS может использовать другие интерфейсы.
После аварийного завершения клиента маршрут к SSH-серверу может
сохраниться до перезагрузки Windows.
